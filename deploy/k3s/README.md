# Kubernetes deployment (k3s, kube-prometheus-stack)

The central server and assessment worker run in Kubernetes. Agents run as systemd
services on each host: an agent in a container would inventory the container, not the host.

```
host (systemd)                       namespace software-inventory
software-inventory-agent  --push-->  pod: server ── SQLite (PVC) ── assess
  every 12 h                              │                         ├ Arch tracker, hourly
                                          │                         ├ OSV.dev, every 6 h
                                          │                         └ NIST NVD CVSS
                                          └─ /metrics ── ServiceMonitor ──> Prometheus ──> Grafana
```

| File | Contents |
|---|---|
| `inventory.yaml` | Namespace, PVC, Deployment (server + assess), Service, ServiceMonitor |
| `grafana-dashboard.yaml` | Dashboard ConfigMap, generated by `gen_dashboard.py` |

## Prerequisites

- **kube-prometheus-stack** with Helm release name `monitoring`. The ServiceMonitor is
  labelled `release: monitoring`; change it if your Prometheus selects other labels:
  `kubectl get prometheus -A -o jsonpath='{..serviceMonitorSelector}'`.
- **Grafana sidecar** loading ConfigMaps labelled `grafana_dashboard: "1"` from all
  namespaces (the chart default), and a Prometheus datasource with UID `prometheus`.
- **A `local-path` StorageClass** (the k3s default). Any ReadWriteOnce class on a local
  disk works; SQLite must not sit on a network filesystem.

## Install

```sh
kubectl apply -f deploy/k3s/inventory.yaml

# One read token (API and Prometheus) and one upload token per host ID.
READ=$(openssl rand -hex 32); WEB01=$(openssl rand -hex 32)
kubectl create secret generic software-inventory-credentials -n software-inventory \
  --from-literal=read_token="$READ" \
  --from-literal=credentials.json="{\"read_token\":\"$READ\",\"hosts\":{\"web-01\":\"$WEB01\"}}"

kubectl apply -f deploy/k3s/grafana-dashboard.yaml
kubectl rollout status -n software-inventory deploy/software-inventory
```

The image is `ghcr.io/brighk/software-inventory-exporter`, built for amd64 and arm64.
To run your own build without a registry on k3s:

```sh
docker build -t ghcr.io/brighk/software-inventory-exporter:0.2.0 .
docker save ghcr.io/brighk/software-inventory-exporter:0.2.0 | sudo k3s ctr images import -
```

### Optional: NVD API key

Without a key, CVSS lookups take about 6 seconds per new CVE. A
[free key](https://nvd.nist.gov/developers/request-an-api-key) makes them ~10× faster:

```sh
kubectl patch secret software-inventory-credentials -n software-inventory \
  --type merge -p '{"stringData":{"nvd_api_key":"YOUR-KEY"}}'
kubectl rollout restart -n software-inventory deploy/software-inventory
```

## Connect agents

**The Kubernetes node itself:** the server container publishes `hostPort` 9899 on
`127.0.0.1` only, so an agent on the node uses `--server http://127.0.0.1:9899`.
Nothing is exposed on the LAN. Remove the `hostPort` if you don't need it.

**Other hosts:** agents require HTTPS. Expose the `software-inventory` Service with
an Ingress (Traefik ships with k3s) and a TLS certificate, for example from cert-manager,
or reach it over a VPN. For a private CA, give agents `--ca-cert`. Expose only
`/v1/inventory` publicly if you can: the read endpoints and `/metrics` need the read token,
but a smaller surface is better.

Install the agent as described in the [README](../../README.md#2-agent-on-each-host).

**Adding a host:** add its ID and a new token to `credentials.json` in the Secret, then
`kubectl rollout restart -n software-inventory deploy/software-inventory`.

## Check

```sh
journalctl -u software-inventory-agent -n 20            # on a host
kubectl logs -n software-inventory deploy/software-inventory -c assess
READ=$(kubectl get secret -n software-inventory software-inventory-credentials -o jsonpath='{.data.read_token}' | base64 -d)
kubectl port-forward -n software-inventory svc/software-inventory 9899 &
curl -s -H "Authorization: Bearer $READ" http://127.0.0.1:9899/v1/assessment-status
curl -s -H "Authorization: Bearer $READ" 'http://127.0.0.1:9899/v1/findings?status=affected,needs_review'
```

In Prometheus, the target `serviceMonitor/software-inventory/software-inventory/0` should
be up. The Grafana dashboard is **Software Inventory** (UID `software-inventory`).

The assess container needs outbound HTTPS to `security.archlinux.org`, `api.osv.dev`
and `services.nvd.nist.gov`. If one is unreachable, the worker keeps its last results,
turns the corresponding dashboard stat red, and retries (tracker hourly, OSV and NVD
every 10 minutes).

## Upgrade

Back up the database first: `kubectl cp` from `/data` while the pod runs, or snapshot the
volume. Then update the image tag in `inventory.yaml` and re-apply. Schema migrations run
automatically. The Deployment uses `Recreate`, so two pods never open the database at once.

To change the dashboard, edit `gen_dashboard.py`, run it, and re-apply the ConfigMap.

## Uninstall

```sh
kubectl delete -f deploy/k3s/grafana-dashboard.yaml
kubectl delete namespace software-inventory   # deletes the database PVC as well
# on each host:
sudo systemctl disable --now software-inventory-agent
sudo rm /etc/systemd/system/software-inventory-agent.service /usr/local/bin/software-inventory-exporter
sudo rm -r /etc/software-inventory-exporter /var/lib/private/software-inventory-agent
```
